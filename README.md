# ev-hub-forecast-value

Code for scoring day-ahead electric vehicle (EV) charging-load forecasts by the operating cost of
PV–storage–charging hubs, under two storage controllers: following the day-ahead plan, and rolling
(shrinking-horizon) re-optimisation. It accompanies a manuscript that is under review; citation details will be
added when it is published.

The pipeline

1. builds hourly station-level charging load from UrbanEV (Shenzhen) and three CHARGED cities (Shenzhen,
   Los Angeles, Melbourne);
2. trains day-ahead forecasts (seasonal naive, four-week mean, DLinear, GRU, Graph-GRU, iTransformer) with MSE,
   MAE, pinball and cost-weighted losses, plus post-hoc cost-aware shifts;
3. sizes a PV–battery–grid hub at every station, schedules the battery with an LP (a small MILP when export and
   import must be exclusive), settles every day hourly against the actual load under the local time-of-use tariff,
   and measures regret against a perfect-foresight oracle;
4. compares accuracy and cost rankings, decomposes regret by error direction and tariff period, estimates
   controller-specific cost weights, and computes station-bootstrap confidence intervals.

**No data or results are included.** The public datasets are downloaded from their original sources by
`scripts/download_data.sh`, and all outputs are regenerated by `scripts/run_all.sh`.

## Repository layout

```
src/
  common.py               dataset selection (DATASET), paths, chronological splits, shared helpers
  preprocess_urbanev.py   UrbanEV station screen and hourly load
  retail_urbanev.py       UrbanEV station retail price (price of shed load)
  preprocess_charged.py   CHARGED site-quality screen and hourly load
  forecast.py             day-ahead forecasts (GPU recommended)
  posthoc_shift.py        post-hoc cost-aware shift of MSE forecasts
  cost_dayahead.py        hub sizing, day-ahead schedule, hourly settlement, oracle and forecast-free rule
  rolling.py              rolling re-optimisation (MPC_PEEK=0: without observing the current hour)
  analysis.py             accuracy vs regret, per-station selection, regret decomposition
  cost_weights.py         per-period under/over-forecast cost weights from calibration regret
  summary_*.py            summary tables and bootstrap intervals across cases
scripts/
  download_data.sh        UrbanEV (Dryad), CHARGED (GitHub), NASA POWER
  run_all.sh              the full pipeline in stages
config/
  prelim_cost_weights.json  preliminary cost weights used by the ph/cost variants of the UrbanEV pool
```

## Data

* UrbanEV: Li et al., *Scientific Data* (2025); full archive on Dryad (station-level files in
  `20220901-20230228_station-processed/features`). Project page: <https://github.com/IntelligentSystemsLab/UrbanEV>
* CHARGED: <https://github.com/IntelligentSystemsLab/CHARGED>, folders `SZH_remove_zero`, `LOA_remove_zero`,
  `MEL_remove_zero`
* NASA POWER hourly all-sky irradiance and 2-m temperature: <https://power.larc.nasa.gov>

Please cite the original dataset publications and respect their licences. Files are placed under `data/dryad/`,
`data/charged/<CITY>/` and `data/nasa/`; the preprocessing scripts write `data/proc/<dataset>/`. NASA POWER data
are occasionally reprocessed, so a fresh download can differ slightly from the one used for the manuscript.

Tariffs, feed-in prices and shed-load prices are public inputs written into `cost_dayahead.py` and
`preprocess_charged.py`, with their sources in the comments.

## Installation

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt   # install the PyTorch build that matches your CUDA version first
```

Linux with bash, `curl` and `unzip`; Python 3.10 or later. The LPs and MILPs use SciPy's HiGHS interface; no
commercial solver is needed.

## Running

```bash
bash scripts/run_all.sh                  # every stage in order
bash scripts/run_all.sh data forecast    # or selected stages
```

| Stage | What it does |
|---|---|
| `data` | download the data and build the station-level inputs |
| `forecast` | all forecasts for the four datasets (GPU recommended), and the UrbanEV variants with the preliminary weights |
| `base` | both controllers on every dataset, calibration and test periods |
| `sensitivity` | UrbanEV hub size, grid limit, tariff, degradation cost, shed-load price and end-of-day valuation cases |
| `seeds` | rolling re-optimisation for training seeds 1 and 2 |
| `nopeek` | rolling re-optimisation without observing the current hour |
| `costaware` | controller-specific cost weights, shifted and cost-trained forecasts, and their scoring |
| `summary` | tables in `outputs/summary/` |

The scoring stages are CPU-bound and run one process per station in parallel; set `NPROC` to the number of
cores to use and `PY` to the Python interpreter. Logs are written to `outputs/logs/`.

### Switches

| Variable / option | Meaning |
|---|---|
| `DATASET` | `uev` (UrbanEV, default), `SZH`, `LOA`, `MEL` |
| `TARIFF` | `sz` Shenzhen (default), `szt` Shenzhen with the test-period flat price, `gd` Guangdong, `sce` SCE TOU-EV-8, `vdo` Victorian Default Offer |
| `DEG_COST` | battery degradation cost per kWh of throughput (default 0) |
| `VOLL_MULT` | multiplier on the shed-load price (default 1) |
| `END_VALUE` | `valley` (default) or `flat`: price of end-of-day battery energy relative to 50% state of charge |
| `MPC_PEEK` | `1` (default) or `0`: whether rolling re-optimisation observes the load of the current hour |
| `--pv`, `--batt`, `--gq` | PV and battery size as shares of mean daily load, grid limit quantile |
| `EV_HUB_ROOT` | folder holding `data/` and `outputs/` (default: repository root) |

### Output tags

Scoring results are written to `outputs/<dataset>/cost_{cal,test}_<tag>.parquet` (one row per station, day and
forecast) with the hub parameters in `hubs_<tag>.csv`.

| Tag | Controller and case |
|---|---|
| `fx_base`, `fx_mpc` | day-ahead following and rolling re-optimisation, base hub |
| `fx_<case>`, `ms_<case>` | the same for a sensitivity case (`pv0`, `pv50`, `b10`, `b50`, `g90`, `g99`, `gd`, `szt`, `deg25`, `deg50`, `v05`, `v2`, `tflat`) |
| `rb_seed` | rolling re-optimisation, seeds 1 and 2 |
| `np_mpc` | rolling re-optimisation without observing the current hour |
| `cw_da_*`, `cw_mpc_*` | controller-specific cost-aware forecasts under each controller |

Forecast files are `outputs/<dataset>/preds_A_<model>_<loss>_s<seed>.npz`. Loss labels `ph` and `cost` use
`config/prelim_cost_weights.json`; `phd`/`costd` and `phm`/`costm` use weights estimated from day-ahead and
rolling regret.

GPU training is not bit-for-bit deterministic, so re-trained forecasts can change the last digits of the
downstream statistics.
